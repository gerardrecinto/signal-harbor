How it works

Deterministic scoring you can explain to the person paged by it.

1

Ingest signals

CI, alerting and security tools post build failures, deploy failures, latency and error spikes, security alerts and database saturation with an API key.

2

Weight by severity

INFO counts 1, WARNING 3, CRITICAL 5. The score is the sum inside the lookback window, and it falls as signals age out.

3

Serve a risk level

LOW, ELEVATED, HIGH or SEVERE per service, cached in Redis and evicted when a new signal lands. Policies are swappable strategies.

Risk levels

LevelScore
LOWbelow 4
ELEVATED4 to 8
HIGH9 to 14
SEVERE15 and above

One CRITICAL deployment failure plus one WARNING latency spike scores 8, which is ELEVATED. The spike policy multiplies the base score once the signal count passes a threshold, to catch many small signals that together mean an outage.

Run it

The README has the full Docker Compose, Jenkins, Kubernetes and Terraform paths.

git clone https://github.com/gerardrecinto/signal-harbor.git
cd signal-harbor
docker compose up
POST /api/v1/signals          # X-API-Key
GET  /api/v1/services/{name}/risk-summary

Java 17 with Spring Boot is the main service. A Python and Django port sits alongside it.

What this does not do
  • It scores signals you send it. It does not collect them or replace your monitoring stack.
  • The weights and thresholds are fixed constants. They rank services for attention and are not a probability of failure.
  • The README calls it a reference implementation. Treat the Terraform examples as starting points.
